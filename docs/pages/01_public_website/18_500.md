# 500 PAGE SPECIFICATION
**HomeLink 2.0 Enterprise Documentation**

## 1. Title & Purpose
**Page Name:** 500
**Module:** 01 PUBLIC WEBSITE
**Purpose:** Menampilkan halaman kesalahan server yang ramah ketika terjadi kegagalan tak terduga di sisi server (mis. `INTERNAL_ERROR` 500 atau `DATABASE_TIMEOUT` 503), memberi pengguna opsi memuat ulang atau kembali ke Beranda tanpa mengekspos detail teknis.

## 2. Next.js Routing Path
```text
app/(01_public_website)/500/page.tsx
```
*(Catatan: pada Next.js App Router, halaman ini secara teknis diimplementasikan melalui `error.tsx`/`global-error.tsx` sebagai Error Boundary; path di atas merepresentasikan lokasi spesifikasi dokumentasi, bukan nama file konvensi Next.js.)*

## 3. Required UI Components (Shadcn/ui)
- `Button` (variant `default`, "Muat Ulang Halaman" — memanggil fungsi `reset()` dari Error Boundary Next.js; variant `outline`, "Kembali ke Beranda")
- (Tidak memerlukan `Card`/`Input`/`Skeleton` — halaman statis tanpa data dinamis)

## 4. Data & State Management
- **Konten:** Sepenuhnya statis; tidak menampilkan detail stack trace atau pesan error mentah ke pengguna akhir (hanya dicatat ke sistem logging/`AUDIT_LOG` di sisi server).
- **Local State:** Tidak ada state UI kompleks; komponen ini menerima props `error` dan `reset` dari Next.js Error Boundary convention.
- **Server State:** Tidak ada fetch data; halaman murni fallback UI.
- **Form Handling:** Tidak ada form pada halaman ini.

## 5. API Endpoints Referenced
- Tidak memanggil endpoint secara langsung. Halaman ini adalah fallback UI yang muncul ketika endpoint apa pun (mis. `GET /api/v1/properties`, `POST /api/v1/bookings`) mengembalikan error tak tertangani seperti `INTERNAL_ERROR` (500) atau `DATABASE_TIMEOUT` (503) sesuai `54_ERROR_CODE_CATALOGUE.md`.

## 6. Acceptance Criteria (DoD)
- [ ] Halaman merespons dengan status HTTP 500 yang benar dan tidak menampilkan stack trace mentah kepada pengguna di lingkungan production.
- [ ] Tombol "Muat Ulang Halaman" memanggil `reset()` dan mencoba merender ulang komponen yang gagal.
- [ ] Tombol "Kembali ke Beranda" berfungsi sebagai jalur pemulihan alternatif.
- [ ] Pesan menjelaskan bahwa ini adalah masalah di pihak sistem (bukan kesalahan pengguna), sesuai aturan copy "tidak menyalahkan pengguna".
- [ ] Error dicatat ke sistem monitoring/logging server-side (bukan hanya ditampilkan ke client).
- [ ] Kontras warna dan tata letak lolos audit Lighthouse Aksesibilitas > 90.
- [ ] Mobile: tombol pemulihan tetap mudah dijangkau (44x44px touch target) dan terpusat.

## 7. Iconography Specification
**Library:** Lucide React ONLY.

#### Icon: `ServerCrash`
- **Purpose & Business Meaning:** Ikon utama ilustrasi halaman 500, menandakan kegagalan di sisi server.
- **Size:** `48px` (ilustrasi hero, lebih besar dari standar UI karena menjadi fokus visual utama halaman error). **Stroke Width:** `1.5`. **Color:** `text-muted-foreground`.

#### Icon: `RefreshCw`
- **Purpose & Business Meaning:** Ikon di dalam tombol "Muat Ulang Halaman".
- **Size:** `20px`. **Stroke Width:** `1.5`. **Hover:** rotasi ringan 150-200ms ease-out saat hover, menghormati `prefers-reduced-motion`.

#### Icon: `Home`
- **Purpose & Business Meaning:** Ikon di dalam tombol "Kembali ke Beranda".
- **Size:** `20px`. **Stroke Width:** `1.5`.

## 8. UI/UX Aesthetic Rules (Mockup Reference)

Halaman ini **DIWAJIBKAN** untuk dibangun dengan mematuhi pedoman visual dari `Mockup.png`: background putih dominan, aksi utama `Royal Blue` (`blue-700`), teks `Dark Navy` (`slate-900`), border radius besar (`16-24px`) pada tombol.

**Spesifik halaman ini:** Sama seperti halaman 404 — layout terpusat penuh (centered), **tanpa** header/navbar sticky dan footer kompleks, agar Error Boundary tetap dapat merender fallback minimal bahkan ketika bagian lain aplikasi (mis. data navigasi) turut gagal.
